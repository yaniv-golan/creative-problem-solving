# Pipeline vs plain prompt — results

Run 2026-08-17 against the design pre-registered in
[`../EXPERIMENT-vs-plain-prompt.md`](../EXPERIMENT-vs-plain-prompt.md). Design, metric and
decision rule were fixed before any data was seen.

**Verdict by the pre-registered rule: effect detected on the prompt that survives. The skill
produces a substantially more mechanism-diverse option set than the same model answering the
same prompt with no skill.**

**Read the scope carefully.** The design pre-registered *two* prompts and required the effect
on **both**. One has been run. The second — the strategic `operating-model-deep` prompt in
`../evals.json` — is **not yet run**, so the pre-registered rule is not yet settled: what
stands is one prompt clearing the threshold, which is exactly the situation the design was
built to avoid.

## Setup

- 10 runs: 1 prompt × 2 arms × 5 repeats, `claude-opus-5`, `fidelity: container`, on the release tree. The
  design's second prompt is not yet run — see the scope note above.
- **Baseline arm generated by the harness's own negative control** (`--ablate-skill`), so it is
  the same runtime, model and tier — not a stale transcript from an earlier iteration.
- Every run verified individually from `result.json` before analysis: treatment runs show
  `ablated: None` with the skill offered *and* invoked; baseline runs show `ablated: true` with
  the skill absent from `availableSkills`. (This check exists because a first attempt at this
  experiment silently produced 10 baseline runs and 0 treatment runs while reporting
  `PASS — 5/5`.)
- Answers scrubbed of process vocabulary, deterministically shuffled, judged blind with no arm
  key. The judge was told to ignore length and format.

## Results

| Metric | **retention, skill** | retention, baseline |
|---|---|---|
| **Distinct mechanisms** (primary) | **6.60** | 4.00 |
| Tail boldness (1–5) | **5.00** | 2.00 |
| Mechanism stated (1–5) | 5.00 | 4.00 |
| Premise tested | **5/5** | 4/5 |

**Delta on the primary metric: +2.60.** Pre-registered detection threshold was 1.0 mechanism.

P2 = "losing senior engineers at 18 months; comp is competitive; it's not the money".
P1 = the strategic `operating-model-deep` prompt — defined, not yet run.

## The strongest evidence is not the averages

The judge was asked whether the ten answers looked like samples from one distribution or fell
into visibly distinct groups. It found **two groups**, called the split unambiguous — *"That is
not a continuum; it is two clusters"* — and assigned every answer.

**Its groups are the arms. 5/5 skill and 5/5 baseline. Ten for ten, blind.**

It also described the treatment group's fingerprint without knowing what it was describing:

> identical scaffolding ("What has to be true / Failure mode / Who runs it" per option; a
> "Cut, and why" section; "What I'd look at first"; a closing "two things you know and I don't")

That is the Phase 4 report template, reconstructed from output alone.

This matters more than the effect size. An effect size at n=5 could be noise; a blinded judge
independently recovering the treatment assignment 10/10 on content, having been told to ignore
the format cues that would have made it easy, is a much harder thing to get by chance.

## What actually separated them

**P2 — the baselines converged on the consensus quartet.** All five produced refresh grants,
staff track, rotation off maintenance, and manager clustering. One **did not test the premise at
all**. The skill runs attacked "it's not the money" with a specified falsifying test (compute
forward unvested value and re-hire price for the last N leavers) and proposed options an asker
would find uncomfortable: acquire negative-margin work to import problem scale, normalise
interviewing with an offer in hand, deliberately rebuild key-person risk, fund the departure.

**P2 is the case the skill previously lost.** In iteration 5 a plain answer beat this pipeline
on this exact prompt by refusing the user's premise while the skill obediently generated
non-money mechanisms. That loss produced Phase 0 step 3b. The fix now holds: 5/5 skill runs
test the premise, against 4/5 baselines that mention it and 1 that ignores it entirely.

## Cost of the win

Deep mode's research produces more checkable factual claims — and therefore more chances to be
wrong. The judge flagged two errors in skill-arm answers (a Midjourney headcount/revenue
conflation; a wrong pre-2020 transformer lead time) and one unplaceable statistic. Baseline
answers made *almost no checkable factual assertions at all* — lower risk, and no evidential
grounding either.

That is the real trade, and the honesty rule is what manages it rather than eliminates it.

## What this does not establish

- **n = 5 per arm, one model, one prompt.** A large effect on a small sample, and the second
  prompt that was supposed to check it is not yet run.
- **It measures output, not process.** Since sub-agent dispatch was removed before release, generation is
  in-context by design and has no tool-stream signature. Nothing here attributes the difference
  to any particular phase — only to the pipeline as a whole.
- **The prompt is strategic.** This says nothing about bounded questions, where iteration 2's
  baseline beat the skill 17/18 to 14/18. The mode gate exists for that case and this experiment
  does not test it.
- The judge is an LLM applying a rubric. It validated itself in the separation pilot by
  discovering a latent grouping (model) unprompted, and here by recovering the arms 10/10 — but
  it is not a human expert panel.
